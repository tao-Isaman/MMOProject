# แผนทำเกมเป็นออนไลน์หลายคน (ร่าง)

> **เอกสารวางแผน ยังไม่ได้เริ่มทำ** เซิร์ฟเวอร์เขียนด้วย Rust และคำนวณทุกอย่างของเกม ส่วนเว็บยังเป็น TypeScript ทำหน้าที่วาดภาพกับรับคำสั่ง

## ภาพรวม

ตอนนี้ทุกอย่างคำนวณในเบราว์เซอร์ ตัวละครเซฟใน localStorage และมีผู้เล่นคนเดียว
แผนนี้ย้าย "ตัวเกม" ทั้งหมดไปไว้ที่เซิร์ฟเวอร์ Rust ซึ่งเป็นเจ้าของความจริงทุกอย่าง:
- **เซิร์ฟเวอร์ทำ:** ตำแหน่ง การชน หาเส้นทาง ค่าสถานะ ดาเมจ สกิล บัฟ มอนสเตอร์ ดรอป กระเป๋า เควสต์ เลเวล อาชีพ และเซฟ
- **เว็บทำ:** วาดโลก 3D ตัวละคร เอฟเฟกต์ UI เสียง กับส่ง "ความตั้งใจ" ของผู้เล่น เช่น เดินไปตรงนี้ ตีตัวนี้ ใช้สกิลนี้

```
เบราว์เซอร์ (TypeScript, three.js)           เซิร์ฟเวอร์ (Rust)                       ฐานข้อมูล
  วาดภาพ / UI / เสียง        <-- WebSocket -->   gateway: login, session, เส้นทางข้อความ    PostgreSQL
  ส่งคำสั่ง ไม่คำนวณผลเอง                        โซนแผนที่: tick 20 ครั้ง/วิ                 บัญชี ตัวละคร
  แสดงสถานะที่เซิร์ฟเวอร์ส่งมา                    (ผู้เล่น มอนสเตอร์ สกิล ดรอป)              กระเป๋า เควสต์ ...
```

## 1. หลักการออกแบบ

1. **เซิร์ฟเวอร์ตัดสินทุกอย่าง** client ไม่เคยส่ง "ดาเมจ" "ได้ของ" หรือ "เลเวลอัป" ส่งได้แค่คำสั่ง กันโกงได้ตั้งแต่โครงสร้าง
2. **คลิกเดินแบบ Ragnarok เหมาะกับเน็ตแล็ก** client ส่งจุดหมาย เซิร์ฟเวอร์หาเส้นทางแล้วเดินให้
   - client ของเราเริ่มเดินทันที (ทำนายไว้ก่อน) แล้วปรับตามเซิร์ฟเวอร์
   - ตัวละครคนอื่นกับมอนสเตอร์ใช้การ interpolate ย้อนหลังราว 100 มิลลิวินาที
3. **ข้อมูลเกมมีที่เดียว:**
   - **ตาราง:** ไอเทม มอนสเตอร์ สกิล ต้นสกิล อาชีพ เควสต์ และร้านค้า ใช้ชุดเดียวกันทั้งสองฝั่ง ไม่เขียนซ้ำสองที่
   - **แผนที่:** เรขาคณิตสำหรับการชนต้องตรงกับภาพที่วาดทุกจุด
4. **ทำเป็นขั้น แต่ละขั้นเล่นได้จริง** ไม่รื้อทั้งเกมทีเดียว และระหว่างพัฒนาโหมดเล่นคนเดียวยังอยู่จนออนไลน์พร้อม

## 2. โครงสร้าง repo

```
/            เว็บเดิม (Vite + TypeScript) ย้ายเข้า client/ หรือคงที่เดิมก็ได้
server/      Cargo workspace
  game/      ตรรกะเกมล้วน (ไม่มี I/O): stats, combat, skills, monsters, items, quests ...
  world/     การชน หาเส้นทาง ความสูงพื้น โหลดข้อมูลแผนที่
  net/       โปรโตคอล ข้อความ การเข้ารหัส
  server/    binary: tokio, WebSocket, โซน, ฐานข้อมูล, auth
  tools/     ตัวทดสอบโหลด บอททดสอบ
shared/
  data/      ข้อมูลเกมเป็น JSON (สร้างจากโค้ด TS ตอน build)
  maps/      ข้อมูลการชนของแต่ละแผนที่ (สร้างจาก builder ของ TS)
  protocol/  นิยามข้อความ -> สร้าง type ทั้ง Rust และ TS
```

## 3. งานที่ต้องทำ แยกตามส่วน

### 3.1 ส่งออกข้อมูลเกม (TS → JSON)
ตารางเกมตอนนี้เป็นโค้ด TS และบางส่วนเป็นฟังก์ชัน เช่น `stats: (r) => ...` หรือ `desc: (r) => ...` ของสกิลแต่ละระดับ
- **สคริปต์ export:** รันใน Node โดยโหลดโมดูล TS แล้วเขียน JSON ฟังก์ชันตามระดับคำนวณออกมาทุกระดับเป็นตาราง เช่น ระดับ 1..max ของแต่ละสกิล
- **ข้อมูลที่ต้องได้:**
  - **อาชีพและเลเวล:** `CLASSES`, `JOBS`, `JOBS3`, `xpToNext`
  - **สกิล:** ต้นสกิล (`TREES`), `ACTIVES`, `MASTERIES`, `ELEMENTS`, `BOOKS`
  - **ไอเทม:** `ITEMS` (รวมไอเทมที่สร้างตามขั้น `t<tier>_*`), `WEAPON_TYPES`
  - **มอนสเตอร์:** `MONSTERS`, `VISITORS`, `PEOPLE` และตารางดรอป
  - **อื่น ๆ:** `QUESTS`, ร้านค้า, สูตรคราฟต์และตีบวก, terrain kinds
- **ตรวจความครบ:** ใส่ hash เวอร์ชันข้อมูลในไฟล์ แล้วให้ client กับ server เช็คตอนเชื่อมต่อ ไม่ตรงกันให้รีโหลด
- **ระยะยาว:** ย้ายตารางไปเป็นไฟล์ข้อมูลล้วน (JSON/RON) แล้วสร้าง type ให้ TS ด้วย `ts-rs` หรือ `typeshare` จะได้ไม่ต้องรัน TS เพื่อดึงข้อมูล

### 3.2 ส่งออกแผนที่ (builder TS → ข้อมูลการชน)
ทุกแผนที่สร้างจากโค้ด (`src/world3d/*`, seed คงที่) จึงสร้างซ้ำได้เหมือนเดิมทุกครั้ง
- **สคริปต์:** โหลด builder ของทุกแผนที่ใน Node (three.js ทำงานได้โดยไม่ต้องมีจอ)
- **ข้อมูลที่ dump ต่อแผนที่:**
  - `bounds`
  - `solids` (วงกลมและกล่องหมุน)
  - ตารางความสูงพื้นเป็น grid เช่นช่องละ 50 ซม. หน้าผากันเดินมีอยู่ใน solids แล้ว
  - `warps` กับ `gates`
  - จุดเกิดมอนสเตอร์ (`spots`) และช่วงเลเวล
  - NPC: ตำแหน่ง บทบาท และร้าน
  - จุดเกิดของผู้เล่น
- **ฝั่ง Rust:** port `src/world.ts` (`resolve`, `blocked`, `clearLine`, `findPath`) กับ `heightAt`
- **เช็คความตรงกัน:** เขียนเทสต์ที่ส่งจุดชุดเดียวกันเข้าทั้ง TS และ Rust แล้วผลต้องตรงกัน

### 3.3 ตรรกะเกมที่ต้องเขียนใหม่ใน Rust (หัวใจของงาน ~10–12k บรรทัด TS)

| ระบบ | ไฟล์เดิม | หมายเหตุ |
|---|---|---|
| ค่าสถานะ | `stats.ts`, `hero.ts` (job3Stats, terrain buffs) | `computeStats` ทั้งหมด เพดานค่าต่าง ๆ |
| ดาเมจ | `stats.ts`, `combat.ts` | ตีกาย/เวท คริ หลบ ธาตุ เผ่า เจาะเกราะ ดาเมจมือรอง ระยะโจมตี รูปพื้นที่สกิล |
| สกิล | `skills.ts` (1,047 บรรทัด) | เวลาร่าย คูลดาวน์ MP กลไกพิเศษทั้งหมด (กับดัก เหยี่ยว พิษ ระเบิดพิษ ลูกเต๋า เหรียญ ซ่อนตัว ฯลฯ) |
| บัฟ สถานะผิดปกติ | `hero.ts`, `monsters.ts`, `poisons.ts` | ติดไฟ แช่แข็ง หิน ช้า ตาบอด ฯลฯ |
| มอนสเตอร์ | `monsters.ts`, `bestiary.ts` | AI ทุก behaviour (พุ่งชน รุม ยิง บิน ฟื้นตัว หนี สะท้อน ระเบิด ขโมย เรียกลูกน้อง) เกิดใหม่ บอส 1 ชม. |
| พันธมิตร | `allies.ts` | ตัวที่อัญเชิญ ตัวล่อ |
| เลเวล อาชีพ | `progression.ts` | EXP ลดตามช่องว่างเลเวล แต้มสกิล เปลี่ยนอาชีพ |
| ดรอป | `drops.ts`, ส่วนใน `main.ts` | ใครเก็บได้ (เจ้าของดรอปช่วงแรก แล้วเปิดให้ทุกคน) |
| กระเป๋า อุปกรณ์ | `inventory.ts`, `items.ts` | ใส่/ถอด มือหลัก/รอง สองมือ ขาย ทิ้ง |
| ร้าน คราฟต์ ตีบวก | `shop.ts`, `workshop.ts` | ราคา ส่วนลดจากตำราพ่อค้า โอกาสตีบวก |
| เควสต์ | `quests.ts`, `quests_job3.ts`, `jobmasters.ts` | นับการล่า เก็บของ คุยกับ NPC รางวัล |
| การเดินทาง | `maps.ts`, warp, travel guide, เรือ, จุดเซฟ | ค่าเดินทาง ฟื้นที่จุดเซฟ |
| บอทล่าอัตโนมัติ | `bot.ts` | ดูข้อ 5 |

**วิธีกัน port ผิดสูตร:** ทำ golden tests โดยรันสูตร TS กับชุด input แบบสุ่มจำนวนมาก (ค่าสถานะทุกอาชีพทุกเลเวล ดาเมจทุกอาวุธ สกิลทุกระดับ) บันทึกผลเป็นไฟล์ แล้วให้ Rust ต้องได้ผลตรงกัน ค่าสุ่มคุมด้วย seed เดียวกัน

### 3.4 เซิร์ฟเวอร์ (Rust)
- **stack:** `tokio` + `axum` (HTTP และ WebSocket) + `sqlx` (PostgreSQL) + `serde`
  - ข้อความใช้ `postcard` หรือ `bincode` ถ้าอยากให้ TS อ่านง่ายใช้ MessagePack
  - log ใช้ `tracing`
- **โซน:** หนึ่งแผนที่ = หนึ่ง task ที่ tick 20 ครั้งต่อวินาที (ต่อยอดเป็น ECS เช่น `bevy_ecs` หรือ `hecs` ได้ถ้าโต)
  - แผนที่ที่ไม่มีผู้เล่นให้หลับ ไม่ต้องคำนวณมอนสเตอร์
  - ย้ายแผนที่ (warp) = ส่งตัวละครจากโซนหนึ่งไปอีกโซน
- **ส่งข้อมูลเฉพาะที่จำเป็น (interest management):** ผู้เล่นได้รับเฉพาะสิ่งที่อยู่ในรัศมีจอ ส่งเป็น delta ไม่ส่งทั้งโลก
- **กันสแปม:** จำกัดจำนวนคำสั่งต่อวินาที ตรวจระยะ คูลดาวน์ และ MP ทุกครั้ง
- **เซฟ:**
  - บันทึกลงฐานข้อมูลทันทีเมื่อเกิดเหตุการณ์สำคัญ เช่น เลเวลอัป ได้ของ เปลี่ยนอาชีพ ซื้อขาย
  - เซฟเป็นรอบทุก 30–60 วินาที และตอนออกจากเกม
  - การเทรดทำใน transaction เดียว กันของงอก
- **บัญชี:** สมัครด้วยอีเมลกับรหัสผ่าน (argon2) หรือ OAuth (Google) แล้วใช้ session token
- **ฐานข้อมูล:**

| ตาราง | เก็บอะไร |
|---|---|
| accounts | บัญชีผู้ใช้ |
| characters | ชื่อ หน้าตา อาชีพ เลเวล EXP ทอง จุดเซฟ |
| skills | แต้มสกิลที่ลงแล้ว |
| inventory | กระเป๋า |
| equipment | ของที่สวมใส่ |
| quests | ความคืบหน้าเควสต์ |
| bot_settings | การตั้งค่าบอท |
| storage | คลังเก็บของ (ภายหลัง) |
| parties, guilds | ปาร์ตี้และกิลด์ (ภายหลัง) |

### 3.5 โปรโตคอล (ข้อความหลัก)
- **client → server:**
  - เข้าเกม: `Login`, `CreateCharacter`, `EnterWorld`
  - การกระทำ: `MoveTo(x,y)`, `Attack(target)`, `CastSkill(id, target|point)`, `CancelCast`
  - ไอเทม: `UseItem`, `Equip/Unequip`, `PickUp(drop)`, `Drop/Sort`
  - NPC: `Talk(npc)`, `Buy/Sell`, `Refine/Craft`, `QuestAccept/QuestTurnIn`, `Travel(dest)`, `SaveSpot`
  - แต้มและบอท: `RaiseNode(tree,node)`, `RaiseMastery`, `RaiseElement`, `ReadBook`, `BotStart/Stop/Settings`
  - สังคม: `Chat(channel,text)`, `Party*`, `Trade*`
- **server → client:**
  - สถานะแผนที่: `Welcome`, `MapEnter(map, you, entities)`
  - เอนทิตีรอบตัว: `Spawn/Despawn(entity)`, `Snapshot(delta)` (ตำแหน่ง เป้าหมาย HP% สถานะ)
  - ผลการต่อสู้: `Hit(attacker, target, dmg, crit, miss, element)`, `SkillFx(...)`, `Death`, `Respawn`
  - ตัวละครของเรา: `Stats/Hp/Mp`, `Xp/LevelUp`, `Inventory delta`, `Quest update`
  - อื่น ๆ: `Chat`, `Error(reason)`
- นิยามข้อความเขียนที่เดียว แล้วสร้าง type ให้ทั้ง Rust และ TS อัตโนมัติ

### 3.6 ฝั่งเว็บ (TypeScript)
- **ชั้นเครือข่าย:** WebSocket เชื่อมต่อใหม่อัตโนมัติ ถอดรหัสข้อความ และนาฬิกาซิงก์กับเซิร์ฟเวอร์
- **แยก "จำลอง" ออกจาก "วาด":**
  - `main.ts` ตอนนี้รวมทั้งสองอย่าง โค้ดคำนวณ (ดาเมจ ดรอป EXP) ต้องถอดออก แล้วให้ฉากวาดตามสถานะที่เซิร์ฟเวอร์ส่งมา
  - คลาส `Player` และ `Monster` เหลือแค่ส่วนแสดงผล คืออนิเมชัน ทิศ และ interpolation
  - ตัวเลขลอย เอฟเฟกต์ และเวทวงกลมเล่นตาม event จากเซิร์ฟเวอร์
- **ผู้เล่นคนอื่น:** วาดด้วยระบบหน้าตาเดิม (`look.ts`) มีป้ายชื่อและอาชีพ แคชชีตตามหน้าตาเพราะคนเยอะ
- **หน้าแรก:** หน้า login หรือสมัคร แล้วดึงรายชื่อตัวละครจากเซิร์ฟเวอร์แทน localStorage
- **UI ใหม่:** แชท ปาร์ตี้ เทรด และรายชื่อผู้เล่นในแผนที่
- **โหมดเล่นคนเดียว:** เก็บไว้ระหว่างพัฒนาโดยใช้ `ServerLocal` จำลองเซิร์ฟเวอร์ในเบราว์เซอร์ (หรือคอมไพล์ Rust เป็น WebAssembly) client จะคุยผ่าน interface เดียวกันทั้งสองแบบ

### 3.7 ระบบใหม่ที่มีเพราะเป็นออนไลน์
- **ปาร์ตี้:** แบ่ง EXP ตามระยะและเลเวล บัฟและฮีลใส่เพื่อนได้ (สกิลบางตัวตอนนี้ใส่ได้แค่ตัวเอง)
- **เทรด:** ผู้เล่นแลกของกันแบบสองฝั่งยืนยัน
- **แชท:** แผนที่ ปาร์ตี้ กระซิบ และตัวกรองคำ
- **ความเป็นเจ้าของ:** มอนสเตอร์และดรอปเป็นของคนที่ทำดาเมจมากที่สุด
- **บอส:** เกิดทีละตัวทั้งเซิร์ฟเวอร์ ประกาศตอนเกิด
- **ระบบดูแล:** แบน เตะ และ log การซื้อขายกับการได้ของหายาก

## 4. แผนที่และเรือ
- warp, travel guide และเรือเป็นคำสั่งไปเซิร์ฟเวอร์ ซึ่งตรวจค่าเดินทางกับเงื่อนไข แล้วย้ายตัวละครข้ามโซน
- แผนที่โลก (M) ใช้ข้อมูลเดิมฝั่ง client ได้ ไม่ต้องพึ่งเซิร์ฟเวอร์

## 5. บอทล่าอัตโนมัติ (ต้องตัดสินใจ)
บอทเป็นฟีเจอร์ของเกมนี้ แต่ในออนไลน์มีผลกับเศรษฐกิจและโหลดเซิร์ฟเวอร์ เลือกได้ 3 แบบ:

| แบบ | ข้อดี | ข้อเสีย |
|---|---|---|
| **ก. บอทอยู่ฝั่งเซิร์ฟเวอร์** ทำงานเฉพาะตอนออนไลน์ (แนะนำ) | ตัดสินใจด้วยกฎเดิม กันโกงง่าย เน็ตหลุดก็ไม่มีปัญหา | กิน CPU เซิร์ฟเวอร์ ต้องจำกัดเวลาหรือจำนวน |
| ข. บอทอยู่ฝั่ง client ส่งคำสั่งเหมือนคนกด | เซิร์ฟเวอร์ไม่ต้องคิดแทน | ต้องเปิดเบราว์เซอร์ทิ้งไว้ |
| ค. บอททำงานต่อแม้ออฟไลน์ (เหมือนเกมมือถือ) | สะดวกผู้เล่น | โหลดสูง เศรษฐกิจเฟ้อ ต้องคุมเพดาน |

## 6. โฮสต์และค่าใช้จ่าย
- **เว็บ:** อยู่บน Vercel ต่อได้ (ไฟล์ static)
- **เซิร์ฟเวอร์ Rust:** ต้องเปิดค้างและรับ WebSocket ได้ ซึ่ง Vercel ทำไม่ได้ ใช้ Fly.io, Railway หรือ VPS (Hetzner/DigitalOcean)
  - เริ่มที่ 1 เครื่อง 2–4 vCPU รองรับราว 200–500 คนพร้อมกัน แล้วแต่จำนวนมอนสเตอร์และบอท
- **ฐานข้อมูล:** PostgreSQL แบบ managed เช่น Supabase ซึ่งมี connector ในเซสชันนี้อยู่แล้ว หรือ Neon หรือ Postgres บน VPS เดียวกันก็ได้
- **โดเมนกับ TLS:** ต้องใช้ `wss://` และตั้ง CORS ให้ตรงโดเมน
- **การดูแล:** health check, log, สำรองฐานข้อมูลรายวัน และอัปเดตเซิร์ฟเวอร์โดยไม่ให้ผู้เล่นหลุด (เตือนก่อนแล้วรีสตาร์ต)

## 8. ความเสี่ยง
- **สูตร Rust ไม่ตรงกับ TS:** สกิลมีกลไกเฉพาะเยอะ ต้องพึ่ง golden tests และแนะนำให้หยุดเพิ่มกลไกใหม่ระหว่าง port
- **แผนที่ไม่ตรงกัน:** ถ้า builder เปลี่ยนแต่ลืม export ใหม่ การชนจะผิด ต้องผูก export เข้ากับ build และเช็ค hash
- **โหลดเซิร์ฟเวอร์:** มอนสเตอร์หาเส้นทางพร้อมกันหลายแผนที่ บวกบอทของทุกคน ต้องให้โซนที่ว่างหลับ และจำกัดความถี่การหาเส้นทาง
- **เซฟเก่าใน localStorage:** ตัวละครเดิมย้ายขึ้นเซิร์ฟเวอร์ตรง ๆ ไม่ได้ เพราะแก้ไขเองได้ ต้องเลือกระหว่างเริ่มใหม่ หรือย้ายแบบจำกัด เช่น เลเวลกับอาชีพเท่านั้น
- **ความหน่วงเน็ต:** เกมคลิกเดินแบบ RO ทนแล็กได้ดี แต่สกิลที่เล็งพื้นที่ต้องให้ภาพตอบสนองทันทีแล้วค่อยรอผลจากเซิร์ฟเวอร์
